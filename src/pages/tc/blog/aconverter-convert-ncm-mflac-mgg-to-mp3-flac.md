## 為什麼音樂軟體要把音樂鎖進 .ncm 和 .mflac / .mgg？

很多朋友誤以為只要自己是「黑膠 VIP」或者「綠鑽豪華會員」，下載下來的就是屬於自己的音訊檔案。事實並非如此：

```text
[使用者付費下載] 
      │
      ▼
[專屬封裝加密]
 ├─ 網易雲音樂: .ncm (AES 金鑰封裝的混淆容器)
 ├─ QQ 音樂標準品質: .mgg (加密 Ogg 封裝)
 └─ QQ 音樂無損品質: .mflac (混淆標頭與金鑰流的 FLAC 容器)
      │
      ▼
[非官方播放器] ──(無法讀取私有格式)──► [車載音響/DAP 報錯跳過]
```

這些專屬格式存在兩大致命傷：
1. **裝置排他性**：普通的汽車中控主機、可攜式無損播放器（DAP）、家用 CD / 串流播放解碼器根本沒有這些軟體的私有解密憑證，直接當作損壞檔案處理；
2. **時效性封鎖**：只要會員一到期，或者應用程式版本一更新，原本離線在本機的歌曲甚至會在客戶端裡「變灰」無法播放。

## 傳統解決辦法的 2 大避坑點

在找到 AConverter 之前，我測試過市面上常見的兩類替代方案，但都有明顯的缺陷：

### 1. 線上網頁端轉換工具（隱私黑洞與大小限制）
很多所謂的「線上音訊轉換」網頁，要求使用者把整首歌上傳到他們的遠端伺服器。
* **速度緩慢**：一首無損歌曲 30MB~50MB，上傳需要十幾秒，轉碼排隊一分鐘，下載又要十幾秒；
* **檔案大小限制**：未付費使用者限制單一檔案 50MB 以內，長音訊或整張母帶大包直接報錯；
* **隱私與版權風險**：你的個人音訊被長期快取在第三方未知伺服器上，風險極大。

### 2. GitHub 開源命令列腳本（環境門檻高）
雖然開源社群有部分 Python / Node 指令碼，但對 macOS 一般使用者極不友善：需要手動安裝 Homebrew、配置 Python 環境、安裝 ffmpeg 依賴，稍微遇到一個權限錯誤就卡住不動。

## 使用 AConverter 本機極速轉換實作

AConverter 是原生的 macOS 應用程式，其底層解密與音訊重新封裝引擎**完全運行在 Mac 本機**，無需上傳任何資料，單曲轉換僅需 1~2 秒。

### 第一步：批次拖入專屬格式音訊
打開 AConverter，直接將網易雲音樂或 QQ 音樂的下載快取目錄（通常在 `~/Music/` 或客戶端設定的離線目錄）中的 `.ncm`、`.mflac`、`.mgg` 檔案拖入軟體視窗中。支援多選直接拖入，數量不限。

### 第二步：選擇目標格式與位元率
根據你的播放裝置選擇目標格式：
* **車用隨身碟首選**：目標格式選擇 **MP3**，位元率選擇最高檔位 **320 kbps**，取樣率設定為 **44,100 Hz**。這種組合相容 99.9% 的各類汽車中控（從傳統油車到最新款電動車主機）；
* **無損隨身聽 / 耳擴首選**：如果原檔案是 QQ 音樂的 `.mflac` 或網易雲的無損品質，目標格式直接選擇 **FLAC** 或 **WAV**，輸出無損母帶級原汁原味音質。

### 第三步：一鍵開啟多任務極速轉換
在右上方將任務並行數拉到 **8 執行緒**（充分利用 Apple M 系列多核心晶片），點擊「開始轉換」。

實測在 MacBook Pro（M3 晶片）上：
* 80 首 網易雲 `.ncm` 檔案（共約 2.4 GB）：**耗時僅 28 秒**全部轉換完畢；
* 原歌曲的專輯封面、歌名、演出者標籤中繼資料（ID3 Tag）100% 完整保留，沒有出現任何亂碼。
