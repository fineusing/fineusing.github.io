## 為什麼舊版 Launchpad 的固定網格如此違反人體工學？

蘋果在設計原生啟動台時，沿用了自 iPad 移植而來的固定比例思維：在多數版本中，行數與列數通常被粗暴地鎖定在 **5 行 × 7 列（最多 35 個圖示）**。

這種一刀切的設計在現代多螢幕工作流中暴露出極大的痛點：

1. **大螢幕空間利用率極低**：在 4K/5K 甚至超寬螢幕上，原本能夠一覽無遺收納所有高頻工具的充裕面積，被蘋果白白浪費了 60% 以上。你明明安裝了 80 多款軟體，卻不得不頻繁在兩三個分頁之間來回翻找；
2. **圖示大得像長輩機介面**：過於龐大的圖示不僅視覺笨拙，而且大幅拉長了眼球巡視路徑，在大螢幕上找 App 就像在做視力檢查；
3. **傳統終端機指令極為脆弱**：許多資深使用者曾嘗試在終端機輸入：
   ```bash
   defaults write com.apple.dock springboard-columns 10
   defaults write com.apple.dock springboard-rows 8
   killall Dock
   ```
   這種改法存在嚴重的副作用：只要系統小版本更新或 Dock 重啟，網格經常瞬間被打回預設原形；更慘的是，先前好不容易分類建好的數十個分組資料夾，會被終端機指令強行「打散重設」，圖示散落一地，讓人欲哭無淚。
