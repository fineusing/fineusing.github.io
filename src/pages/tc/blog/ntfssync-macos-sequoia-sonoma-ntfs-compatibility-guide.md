## 為什麼升級系統後，舊款 NTFS 驅動程式總會癱瘓？

在新版 macOS（特別是 Sonoma 與 Sequoia）中，Apple 對作業系統的底層安全性進行了兩項重大強化：

1. **全面廢棄舊版核心介面與私有符號**：早年許多第三方驅動程式採用「走後門」的方式，呼叫未公開的 macOS 核心私有函式來攔截磁碟讀寫。在新系統中，這些私有符號被 Apple 徹底清除或強制沙盒隔離，老舊驅動程式直接載入失敗。
2. **徹底封死終端機指令原生掛載漏洞**：在十年前的 macOS 舊版本中，進階玩家可以透過在終端機輸入 `mount -o rw -t ntfs /dev/diskXsX ...` 強行啟動 Apple 內建的實驗性 NTFS 寫入功能。但在 Sonoma 及後續版本中，Apple 底層重構了檔案系統架構，該隱藏參數已被徹底移除，任何強制掛載都會直接回傳 `Operation not permitted` 或導致檔案系統損毀。

因此，高度依賴老舊方案的電腦一旦升級系統，便會立刻陷入「軟體報錯、硬碟唯讀、找不到替代方案」的惡性循環。

## 解決外接硬碟唯讀與無法寫入的三個排查步驟

遇到外接儲存裝置在 macOS Sonoma / Sequoia 上變成唯讀或無法寫入時，請依照下列邏輯依序檢查：

### 第一步：確認磁碟檔案系統格式與權限
- 將外接硬碟或隨身碟連接至 Mac；
- 在桌面上選取該硬碟圖示，按下快速鍵 `⌘I` 開啟「取得資訊」；
- 查看最下方的「共享與權限」：若是 Windows 格式的硬碟，通常會顯示「您只能讀取」，格式欄位明確標示為 **Windows NT 檔案系統（NTFS）**。

### 第二步：排查 Windows「快速啟動」導致的磁碟鎖定（Dirty Bit）
許多時候，硬碟呈現唯讀狀態並非 Mac 的問題，而是 Windows 的機制所致：
- Windows 10 與 11 預設啟用了「快速啟動（Fast Startup）」功能；
- 當你在 Windows 電腦上點擊「關機」時，系統實際上是將核心狀態儲存到硬碟中，並未真正完全卸載 NTFS 分割區，並會在檔案系統標頭打上一個「Dirty Bit（不正常關機/髒標記）」；
- 當 Mac 偵測到這個未完全關閉的安全標記時，為了避免覆寫破壞現有資料，會強制拒絕寫入。此時需要使用具備修復功能的工具清除該標記。

### 第三步：採用現代免核心驅動工具實現隨插即用

與其每年升級系統都提心吊膽地等待老舊驅動程式更新修正檔，最穩妥的解法是轉換到底層基於 **FUSE-T + NFS v4 使用者態架構**的工具——[NTFSSync](https://apps.apple.com/app/id6475194342)。

由於 NTFSSync 純粹在使用者空間（Userspace）執行，完全不依賴被 Apple 廢棄的核心符號：
- **無縫適配新系統**：無論是 macOS Sonoma、Sequoia 還是未來的全新版本，NTFSSync 均能原生無痛相容；
- **零安全性降級**：你無須關機進入復原模式去修改開機安全性設定，完整保留系統原廠的 SIP 防護；
- **全自動掛載**：安裝後接上 NTFS 裝置，秒速自動掛載為可讀寫狀態，在 Finder 中直接拖曳大檔案、重新命名或編輯文件。

## 額外驚喜：在 Sequoia / Sonoma 上直接格式化為 NTFS

在 macOS 內建的「磁碟工具程式（Disk Utility）」中，點擊「抹除」依然僅有 APFS、Mac OS 擴充格式、ExFAT 與 FAT32 選項。

若你需要把手邊的隨身碟或外接硬碟準備成純淨的 Windows 格式：
1. 開啟 **NTFSSync**；
2. 在裝置清單中選取該外接磁碟機；
3. 點選「格式化為 NTFS」，輸入自訂的磁碟標籤名稱；
4. 幾秒鐘內即可直接在 Mac 上產生一個標準的 NTFS 分割區，插上任何 Windows 電腦都能暢行無阻。
