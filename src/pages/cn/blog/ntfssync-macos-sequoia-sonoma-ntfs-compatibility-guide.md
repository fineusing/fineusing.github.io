## 为什么升级系统后，旧的 NTFS 驱动总会瘫痪？

在新版 macOS（特别是 Sonoma 与 Sequoia）中，苹果对操作系统的安全性进行了两项重大加固：

1. **废弃旧版内核接口与私有符号**：早年很多第三方驱动采用“旁门左道”，调用未公开的 macOS 内核私有函数来截获磁盘读写。在新系统中，这些私有符号被苹果彻底清除或强制沙盒化，老旧驱动直接加载失败。
2. **彻底封死终端命令行原生挂载漏洞**：在十年前的 macOS 时代，极客们可以通过在终端输入 `mount -o rw -t ntfs /dev/diskXsX ...` 强行激活苹果自带的实验性 NTFS 写入功能。但在 Sonoma 及后续版本中，苹果底层重写了文件系统架构，该隐蔽参数已被彻底移除，任何强制挂载都会直接抛出 `Operation not permitted` 或导致文件系统损坏。

因此，依赖老旧方案的电脑一旦升级系统，就会立刻陷入“软件报错、硬盘只读、找不到替代品”的恶性循环。

## 解决外接移动硬盘只读与格式化的三个排查步骤

遇到外接存储在 macOS Sonoma / Sequoia 上只读或无法写入时，请按以下逻辑进行检查：

### 第一步：确认磁盘文件系统格式与权限
- 将移动硬盘或 U 盘插入 Mac；
- 在桌面上选中该硬盘图标，按下快捷键 `⌘I` 打开“显示简介”；
- 查看最底部的“共享与权限”：如果是 Windows 格式的硬盘，通常会显示“您只可读（You can only read）”，格式项明确标注为 **Windows NT 文件系统（NTFS）**。

### 第二步：排查 Windows“快速启动”导致的锁定（Dirty Bit）
很多时候，硬盘只读不是 Mac 的问题，而是 Windows 的“锅”：
- Windows 10 和 11 默认开启了“快速启动（Fast Startup）”功能；
- 当你在 Windows 电脑上点击“关机”时，系统实际上是将内核状态保存到硬盘，并没有真正完整卸载 NTFS 分区，并在文件系统头文件中打上了一个“脏标记（Dirty Bit）”；
- 当 Mac 检测到这个未完全关闭的标记时，为了防止数据被覆盖破坏，会强制拒绝写入。此时需要使用具备修复功能的工具清除该标记。

### 第三步：采用现代免内核驱动工具实现即插即用

- **无感适配新系统**：无论是 macOS Sonoma、Sequoia 还是未来的测试版系统，NTFSSync 均能无缝原生兼容；
