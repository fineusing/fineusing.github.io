## 为什么老版 Launchpad 的固定网格如此反人类？

苹果在设计原生启动台时，沿用了从 iPad 搬过来的固定比例逻辑：在多数版本中，行数和列数通常被粗暴地锁死在 **5 行 × 7 列（最多 35 个图标）**。

这种一刀切的设计在现代多显示器工作流下带来了巨大痛点：

1. **大屏空间利用率极低**：在 4K/5K 甚至超宽带鱼屏上，原本可以一屏揽尽所有高频工具的充裕面积，被苹果白白浪费掉了 60% 以上。你明明装了 80 个软件，却必须在两三个分页之间翻来覆去；
2. **图标大得像老人机**：巨型图标不仅视觉笨拙，而且导致眼球巡视路径极长，在大屏上找软件像在看视力表；
3. **老旧终端命令脆弱不堪**：很多老玩家试过在终端里输入：
   ```bash
   defaults write com.apple.dock springboard-columns 10
   defaults write com.apple.dock springboard-rows 8
   killall Dock
   ```
   这种改法有极大的副作用：每次系统小版本更新或重启 Dock，网格经常瞬间被还原回默认状态；更严重的是，原先好不容易分类建好的几十个分组文件夹，会被终端命令粗暴地“打散重置”，图标散落一地，让人欲哭无泪。
